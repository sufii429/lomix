# Lomix

A tiny personal Android app for making a **rainy chill lofi mix** out of any
song on the phone — no big DAW, no accounts, no fees. Pick a song, slow it
down without touching its pitch, lay a ready lofi colour over it, and run
rain underneath. One screen, three big pill tabs.

## What it does (v1 — listening only)

- **Pick a song** with the system file picker (no permissions needed).
- **Speed tab** — audio-stretch slider 0.80x–1.00x (default 0.95x) with the
  pitch locked at 1.0, plus quick chips (0.85 / 0.90 / 0.95 / 1.00).
- **Lofi Rang tab** — four combinable ready effects:
  - *Garam* — warm: low boost + hard top cut (the "Lofi Dirt" shape),
    via the device equalizer.
  - *Naram* — soft: gentle top cut, via the device equalizer.
  - *Geela* — wet: medium-room reverb (PresetReverb).
  - *Vinyl* — a bundled crackle loop playing quietly underneath.
- **Baarish tab** — rain layers with their own volume slider:
  *Koi Nahi* (off), *Halki Raat Wali* (gentle night rain),
  *Tez Barsaat* (heavy rain). Rain and vinyl follow the one master
  Play/Pause button together with the song.
- A bottom strip always shows the current mix, e.g.
  `0.95x · Garam + Vinyl · Halki Raat Wali`.

Exporting the mix to an mp3 file is deliberately **not** in v1 — that is a
phase-2 (ffmpeg) step if it is ever wanted.

## v1.1 additions

- **Background playback** — the players live in a foreground
  `PlaybackService` with a notification (song name, mix summary,
  Play/Pause + Stop), so the mix survives the screen turning off or the
  app being swiped away; the mix state lives in the controller, so a
  reopened app finds everything as it was left.
- **Sleep timer** — Band / 15 / 30 / 60 min chips under the seek bar;
  when it fires, everything pauses.
- **Tin Wali Chhat** — a third rain layer: the same field recording plus
  a dense metallic patter (tin-roof rain), `rain_tin.mp3`.
- **Cassette** — a fifth lofi effect: soft tape hiss (`tape_hiss.mp3`)
  plus a gentle pitch wobble (±0.4%, 5 s period) on the song.
- **Permanent signing key** — debug builds are signed with the project's
  own keystore (`debug-keystore.b64` in the repo root, decoded by
  `app/build.gradle.kts`, stable SHA-1
  45:0E:61:FD:CA:5F:9F:0A:E1:33:89:11:A3:E6:50:74:B3:42:87:DD), so every
  update installs on top of the previous one. (v1.0 was signed by the CI
  runner's one-off key, so moving to v1.1 needs a single uninstall first.)

## Build & install

There is no Gradle wrapper by design: pushes to `main`/`master` run
`.github/workflows/build.yml` on GitHub Actions (JDK 17, Gradle 8.9),
which builds the debug APK and publishes it to the fixed **`build-latest`**
release. The permanent download link is therefore:

```
https://github.com/sufii429/lomix/releases/download/build-latest/app-debug.apk
```

## Audio assets

`app/src/main/assets/` holds three seamless loops generated by
`make_assets.py` (run it with the audio-analysis venv's Python; it needs
ffmpeg on PATH). In this repo the mp3s travel as base64 text under
`assets-b64/` (the GitHub push route is text-only) and
`app/build.gradle.kts` decodes them back into `src/main/assets/` at
build time:

- `rain_gentle.mp3` — 90 s loop from a real gentle night-rain field
  recording (`~/workspace/audio-analysis/Rain_Bed_for_Lofi.mp3`).
- `rain_heavy.mp3` — 90 s loop from the same recording + a synthesized
  high-frequency patter layer, +3 dB.
- `vinyl_crackle.mp3` — 60 s synthesized crackle loop (Poisson clicks +
  faint hiss, generated on a circular buffer so it wraps seamlessly).
- `beats_a.ogg` / `beats_b.ogg` / `beats_c.ogg` — 6 s (2-bar, 80 BPM)
  lofi drum loops, rendered as three copies and cut to the middle one
  so tails wrap seamlessly. Ogg Vorbis because it loops gaplessly
  (mp3 would not). Since v1.2.1 they are built by
  `make_beats_sampled.py` from drum one-shots cut out of Mazeen's own
  reference mix (see the v1.2.1 note below); `make_beats.py` is the
  earlier fully-synthesized generator, kept for reference.

## v1.2 — Beats

A fourth tab adds a drum-beats layer. On song pick, `BeatDetector`
(decode → spectral flux → autocorrelation + comb refinement, all
on-device, no dependencies) finds the tempo and beat phase; the drum
loop is then time-stretched to that tempo — including the slowed
tempo when the speed slider is below 1.00x — and a 250 ms ticker in
the controller phase-locks the loop to the song's beat grid. The user
only picks a style (Balanced / Warm / Bass Boost / Smooth / Dynamic =
EQ curves on the beats session, Dynamic also swaps the loop pattern),
a beats volume, and may nudge the tempo ±0.5 BPM if a song's detected
grid feels off. Algorithm verified offline: Mann Ki Lagan original
73.9 BPM, Mazeen's lofi remix of it 68.0 BPM with a grid phase
constant across the whole song; synthetic 76/92 BPM tracks detected
within 0.05 BPM.

## v1.2.1 — the vibe fix

Mazeen's verdict on the v1.2.0 synthesized loops: sync was right, the
drums felt separate from the song, and later A/B/C synthesized samples
missed too ("mazay ke nahi lagay"). Measuring the beats-only window of
his reference (Mann Ki Lagan – Chill Rainy Lofi, content 56–60 s, hits
exposed without vocals) gave the real recipe: brush on the 2 & 4
backbeat, soft knock kicks dancing around it (bar 1 steps 2,3,6,8,11,14;
bar 2 steps 8,11,14; no kick on beat 1), NO bright hats — only a faint
dark tick — long reverb tails, and every hit machine-tight at a uniform
laid-back offset behind the grid. He also pointed at drum-pad apps
(Super Pads DJ, Drum Pads Go): those beats are recorded sample kits,
which synthesis kept missing.

So v1.2.1's loops are assembled from the reference's own kick and
brush one-shots (`make_beats_sampled.py`), laid out on that measured
pattern with straight (swing-free) timing; the controller keeps the
loop ~30 ms behind the detected grid for the laid-back feel. Styles
now also pick the pattern's fullness: Smooth = sparse `beats_c`,
Dynamic = fuller `beats_b`, the middle styles share `beats_a` and
differ only in EQ. Default beats volume is 60%.

Noted for v1.3 (Mazeen, 2026-11-05): 3–4 in-app drum pads so he can
tap his own pattern and have it join the song via beatsync.

## v1.2.2 — workaround A: the universal recipe

The v1.2.1 sampled loops failed Mazeen's other-song test completely:
drums and pattern both belonged to Mann Ki Lagan. Workaround A (of
two he approved; B = per-song self-beats, later) is the opposite
recipe — `make_beats.py`'s neutral synthesized kit (knock kick, dark
brush, faint tick; voices tuned by the reference measurements but not
copied from any song) under a very simple regular pattern: kick on
beat 1, brush on 2 & 4, one soft kick on the "&" of 3, sparse faint
ticks, straight timing. Loops: beats_a 97,941 / beats_b 97,907 /
beats_c 97,095 bytes.

## v1.3.0 — workaround B: the song's own beats

A second beats source, "Ganay ki apni" (the song's own): `SelfBeats`
uses the detected grid to find the song's cleanest kick-like and
snare-like hits in the decoded PCM (strength + isolation + spectral
gates, prototyped offline on the Mann Ki Lagan original and remix),
cuts them out, and renders the universal pattern as a native-tempo
2-bar WAV loop with a small Schroeder reverb, played phase-locked
like the bundled loops. If the gates fail (no clean drums in the
song), the state shows MISSING and the bundled loops keep playing.
The decoded PCM is kept per song so switching source or style
rebuilds without a second decode. Next on Mazeen's list: in-app drum
pads (noted 2026-11-05).

## v1.4.0 — beats out, Mahaul tab, tayyar gana (stems)

Three changes in one build, on Mazeen's calls of 2026-11-05:

1. **Beats removed.** Three attempts (synthesized loops, a kit sampled
   from the reference song, per-song self-beats) all synced correctly
   and none satisfied — the sound never belonged to the song. The tab
   and playback are gone; the mechanism (BeatDetector, SelfBeats,
   BeatsFx) stays parked in the codebase for future sync use.
2. **Mahaul tab.** The old Baarish tab grew into an ambient-sounds tab:
   rain choices on top, and below them four more looping layers, each
   with its own switch + volume and combinable — Aag (fireplace),
   Lehrein (ocean), Jhingur (night crickets + breeze), Café. All four
   are synthesized by `make_ambience.py` (periodic by construction, so
   the 60 s loops are seamless) and travel as `amb_*.mp3.b64` assets.
3. **Tayyar gana (stems).** Mazeen separates songs himself with MVSEP
   (BS Roformer SW: vocals, bass, drums, guitar, piano, other +
   instrum); the new Hissay tab imports the MVSEP zip (StemStore
   classifies files by the token at the end of each name, and drops
   the "instrum" stem when the detailed music stems exist). Each stem
   plays on its own player with its own copy of the lofi effects; a
   500 ms ticker keeps every stem aligned to the master (vocals) —
   the parked sync idea, reused where it belongs. Per-stem volume
   sliders (0–150%) work like Samsung's Audio Eraser. Speed, Lofi
   Rang, Mahaul and the sleep timer all apply to stem playback too.

## v1.5.0 — Garaj in, Café out, saved mixes, export

Mazeen approved all four of Muse's suggestions plus his own two
calls, in one build:

1. **Café deleted** (his call — the synthesized murmur was the weakest
   layer) and **Garaj added**: a 90 s seamless thunder loop
   (`make_thunder.py`, distant rolling rumbles on near-silence),
   joining Aag / Lehrein / Jhingur in the Mahaul tab.
2. **Hissay quick buttons**: Sab aam (all 100%), Karaoke (vocals 0),
   Drum zyada (drums 140, bass 110, vocals 80).
3. **Sleep-timer fade-out**: over the timer's last 20 seconds every
   player's volume ramps to zero (a single fadeFactor multiplies every
   volume the controller sets), then pause; volumes restore while
   paused so the next Play starts full.
4. **Meray Mix (presets)**: the whole mix — speed, FX toggles, rain,
   ambient switches/volumes, stem volumes — saved under a name in
   SharedPreferences (MixPresets.kt) and re-applied with one tap.
5. **Export to device**: OfflineExporter rebuilds the mix sample by
   sample (decode to canonical PCM → sum the parts → WSOLA stretch
   to the mix speed → the same EQ curves + Schroeder reverb → add the
   looping layers → AAC in an .m4a) and saves it to Music/Lomix via
   MediaStore. The Cassette pitch wobble is the one live effect not
   rendered (its hiss is); ±0.4% shimmer is inaudible in an export.

## v1.6.0 — Queue, playlists, album art, themes

The player grows up (Mazeen's direction, themes approved from a
mockup first):

1. **Queue + auto-play next**: tracks advance by themselves
   (PlayerController's queue engine + the UI poll's onActiveEnded
   hook, which now advances instead of only pausing). Prev/next
   transport buttons, shuffle, and repeat off/all/one.
2. **Library**: every picked song is remembered (LibraryStore);
   a multi-picker adds many at once. **Playlists**: named, ordered
   lists of library songs and tayyar ganay (PlaylistStore), with
   add/remove/reorder and play-from-anywhere — all in the new fifth
   tab, which also shows the live queue.
3. **Album art**: the song file's embedded picture (Artwork, via
   MediaMetadataRetriever) as a banner on the song card and as list
   thumbs; songs without art get a deterministic gradient.
4. **Themes**: Aasmaan (default), iPod Classic, Poweramp Raat —
   one palette object read through composable getters, switched
   from the chips under the header and persisted.
